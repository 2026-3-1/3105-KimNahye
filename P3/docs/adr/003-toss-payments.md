# ADR 003 — 토스페이먼츠 결제 모듈 선택

**날짜**: 2026-05-01  
**상태**: 수락됨

---

## 컨텍스트

P3에서 실제 결제 기능을 구현해야 함. 국내 PG사 선택 기준:
- 무료 체험 코스(0원)부터 유료 코스까지 모두 처리
- Webhook으로 결제 상태 비동기 동기화 필요
- SDK 및 문서 품질

## 결정

**토스페이먼츠(TossPayments)** 채택

## 이유

| PG사 | SDK 품질 | Webhook | 개발자 문서 | 테스트 환경 |
|---|---|---|---|---|
| **토스페이먼츠** | ✅ 공식 SDK | ✅ | ✅ 한국어 상세 | ✅ 무료 |
| 아임포트(포트원) | ✅ | ✅ | ✅ | ✅ |
| KG이니시스 | ❌ 직접 구현 | ❌ | 낮음 | 유료 |

토스페이먼츠를 선택한 이유:
- `@tosspayments/tosspayments-sdk` 공식 React SDK 제공
- 테스트 결제 환경(샌드박스) 무료 제공
- Webhook HMAC-SHA256 시그니처 검증 지원
- 서버 측 금액 재검증 API (`/v1/payments/confirm`) 설계가 명확함

## 구현 흐름

```
클라이언트                서버                  토스
    |                      |                     |
    |-- prepare 요청 ----→ |                     |
    |←- orderId 발급 ------| (DB에 PENDING 주문) |
    |                      |                     |
    |-------- 토스 결제창 오픈 ---------------→ |
    |←-------- 결제 완료 (paymentKey) ----------|
    |                      |                     |
    |-- confirm 요청 ----→ |                     |
    |                      |-- /v1/payments ---→ |
    |                      |   /confirm          |
    |                      |←- 승인 결과 --------|
    |                      | (Enrollment 생성)   |
    |←- 수강 등록 완료 ----|                     |
```

## 결과

- 금액 변조 방지: 서버에서 DB 가격으로 재검증 후 토스 API 호출
- 중복 결제 방지: `paymentKey` DB UNIQUE 체크
- Webhook으로 취소/환불 상태 비동기 동기화

## 트레이드오프

- 0원 결제(무료 코스)는 토스 결제창을 거치지 않고 직접 수강 신청으로 처리해야 함
  → 현재는 장바구니 → confirm 흐름을 통일해서 처리
- 환불 API는 Webhook 수신 후 처리 (사용자 직접 환불 UI는 미구현)
